# Financial Information Hub Launch Blockers

Status as of 2026-08-16: operational production release is blocked. Production is deliberately hard-disabled, no real financial delivery is configured, and the exact command `GO LIVE` has not been received.

| Severity | Blocker / reproduction | Business impact | Required mitigation | Owner / due date |
| --- | --- | --- | --- | --- |
| High | `dev-store.ts` and `accuracy-store.ts` retain records, files, sessions, limits, and audit events only in process memory. | Restart/data loss and no atomic multi-instance workflow. | Approved transactional schema, migrations, encrypted private object storage, least privilege, backups, and tested restore. | System + hosting/data owners; unassigned, before `GO LIVE` |
| High | Requester status/viewer ownership uses a random bearer-style user identifier, not an authenticated account/session. | A leaked identifier may authorize another person. | Expiring authenticated requester session, rotation, reauthentication, server ownership checks, and IDOR tests. | Identity owner; unassigned, before `GO LIVE` |
| High | Existing shared administrator authentication does not prove named approver accounts, MFA, or dedicated least-privilege roles. | Compromise could approve/release restricted records. | Named accounts, MFA, role authorization, disabled-user invalidation, session expiry/rotation, and approval reauthentication. | Identity + business owners; unassigned, before `GO LIVE` |
| High | No durable transactional outbox/provider-state/retry workflow exists. Production financial delivery is absent by design. | Requests could be lost or duplicated and delivery status could be unverifiable. | Approved sender/recipient configuration, atomic outbox, idempotent worker, provider IDs/events, bounded retry, bounce/failure handling, and safe manual retry. | Messaging + data owners; unassigned, before `GO LIVE` |
| High | Upload checks do not include an approved malware service or durable quarantine/private storage. | A crafted allowed file could reach staff. | Private object storage, quarantine, scanner verdict, safe disposition, short-lived authorization, and retention/deletion controls. | Storage/security owner; unassigned, before `GO LIVE` |
| Medium | Exact production recipients, sender identity, CC/BCC confirmation, and test-sink ownership are not represented in protected production configuration. Source intentionally contains no addresses. | Delivery matrix cannot be proven in production. | Owner signoff and protected server configuration, then matrix-based tests without exposing values. | Business + messaging owners; unassigned, before `GO LIVE` |
| Medium | Full `npm run lint` reports 93 errors and 67 warnings in unrelated legacy admin/lounge/game/CAD code. | Existing defects can conceal regressions outside the hub. | Triage and correct without disabling rules. | Respective module owners; unassigned, before general release |
| Medium | Persistent rate limiting, WAF/bot controls, audit sink, monitoring/alerts, TLS/domain/CDN behavior, source maps, storage permissions, preview protection, and deployment takeover posture were unavailable for verification. | Abuse or infrastructure exposure cannot be excluded. | Configure and retain protected-staging/production evidence. | Hosting/security owner; unassigned, before `GO LIVE` |
| Medium | Current Safari/WebKit, Firefox, automated accessibility/screen-reader, and authorized dynamic security scans were not available. | Compatibility, accessibility, or security defects may remain. | Run the documented matrix on protected staging and resolve findings. | QA/accessibility/security owners; unassigned, before `GO LIVE` |
| Medium | `scripts/lounge-init.mjs` and legacy inventory/applicant/board code contain existing staff contacts or recipient addresses. | Repository readers may see staff contact information. | Owner classification, migration to protected configuration where required, history/seed review, and rotation where applicable. | Repository/data owner; unassigned, before general release |
| Medium | Retention, deletion, legal hold, breach response, audit retention, support ownership, and production recovery objectives are not approved in repository requirements. | Sensitive records could be retained or removed inconsistently. | Qualified owner/legal/privacy approval and implementation in durable stores/jobs. | Business/legal/privacy owners; unassigned, before `GO LIVE` |

No unresolved critical defect is known in the reviewed financial source. These high and medium gaps remain safely contained only while the production operational application and delivery stay disabled.
