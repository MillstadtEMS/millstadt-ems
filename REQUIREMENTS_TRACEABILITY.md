# Financial Information Hub Requirements Traceability

This file maps owner-provided requirements to implementation evidence. Legal and disclosure wording is referenced, not rewritten here.

| Requirement | Implementation evidence | Verification |
| --- | --- | --- |
| Preserve the Millstadt site shell, ticker, navigation, weather/alert elements, footer, colors, and brand assets | `components/SiteShell.tsx`, root `app/layout.tsx`, scoped `FinancialsArchivePrototype.module.css` | Desktop/mobile browser screenshots; shell remains outside the component scope. |
| One polished document chooser with multiple checkboxes and a next step | `DocumentLibrarySection` in `FinancialsArchivePrototype.tsx` | Browser flow selects mixed public/restricted documents and remains on the same route. |
| Public Form 990 access has no identity, approval, acknowledgment, or signature gate | Public 990 catalog, HTML, and PDF routes; public-only selection branch | API/browser test confirms no identity field and direct View/Download/Print/Accessible alternative links. |
| Restricted documents require identifying information, exact terms acknowledgment, signature, and approval | Request UI, `validateRequestInput`, signed agreement generator, admin approval route, viewer authorization | API and browser tests cover missing signature, pending denial, approval, expiration/revocation, and viewer access. |
| Request and approval do not expose the public admin queue | Public route contains no admin component; admin UI is under `/admin/financials`; every admin API calls `requireFinancialsAdmin` | Unauthorized admin route/API tests. |
| Call-volume bundle includes the supplied 2022-2026 files and methodology notice | `data/financials-hub/call-volume-requests.pdf`, `.txt`, `.meta.json`; `RUN_COUNT_METHODOLOGY_NOTICE` | `pdfinfo`, text extraction, and rendered 16-page contact sheet. |
| Accuracy/document-integrity reporting is private, signed, and reviewable | Accuracy dialog, CSRF-protected multipart API, server-side validation/upload checks, signed PDF, protected admin queue | API tests for CSRF, upload signatures, protected download, PDF digest, status update. |
| Testing must not send SMS or contact production recipients | Fail-closed production config; empty SMS config; explicit test-delivery gate and test-sink recipient validation | Configuration/notification contract test and dry-run audit entry. |
| No claim that browser screenshots can be universally blocked | Existing release terms state the limitation; reusable Privacy Shield adds honest foreground/background concealment | Privacy Shield browser visibility test and `SECURITY_REVIEW.md`. |
| Sensitive request, signature, review, admin, and viewer states display the screenshot/recording notice and privacy shield | `FinancialsPrivacyShield` component integrated with requester and admin experiences | Mobile/desktop browser checks and component contract test. |
| Sensitive identifiers are not placed in URLs | User identity moved from query strings to request headers/body; viewer/session APIs remain no-store | Source scan and API integration test. |
| Server-side authorization, revocation, expiration, and exact-version checks | `dev-store.ts`, `api-helpers.ts`, protected routes | Direct API tests including unauthorized and stale-state attempts. |
| Deterministic searchable signed PDFs with exact versions, IDs, hashes, signatures, and page numbers | `agreement-pdf.ts`, `accuracy-report-pdf.ts`, stored SHA-256 fields | PDF text checks, page rendering, hash checks, and page-by-page visual review. |
| Catalog page count matches downloadable Form 990 physical pages | `form990PdfBuffer` creates one US Letter PDF page for each catalog page | `pdfinfo` and rendered page regression check for both synthetic filings. |
| Production remains Coming Soon until exact `GO LIVE` | `getFinancialsHubConfig` fails closed in production; financial page renders the restricted production experience; APIs return 404 while disabled | Production-build/start smoke test with operational routes blocked. |
| Installable app metadata without confidential offline caching | Dedicated manifest/icons and a service worker that does not cache requests, responses, admin pages, submissions, or documents | Manifest/service-worker contract test and browser registration check. |
| Do not add financial production secrets or real financial recipient addresses to source/client bundles | Environment-only financial server config, placeholder examples, and recipient-free client responses | Staged financial-source and credential-pattern scans documented in `TEST_EVIDENCE.md`; unrelated legacy contact findings remain in `BLOCKERS.md`. |
| Do not claim production readiness while persistence, durable delivery, release auth, and retention are absent | Production remains disabled; gaps are explicit in `BLOCKERS.md` and `SECURITY_REVIEW.md` | Release checklist must fail closed until blockers are resolved. |
